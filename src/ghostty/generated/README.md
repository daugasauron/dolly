# Generated Ghostty Zig source

These files are source inputs, not packaged WebAssembly, C, object files, or
archives. Zig compiles them to Wasm inside the `ghostty-build` image rebuild.
Other images copy the finished terminal plugin; prebuilt boots do not compile it.

They were generated by the official Zig 0.17.0 build graph for Ghostty v1.4.0
(commit `83fb95624b0439ee660c2679b43b38c8b63769cd`), run in its checkout with:

```sh
ZIG_GLOBAL_CACHE_DIR=GLOBAL_CACHE zig build --cache-dir CACHE --cache-poison=poisoned \
  --prefix PREFIX -Demit-lib-vt=true -Dtarget=wasm64-emscripten -Dcpu=generic \
  -Doptimize=ReleaseSmall
```

The build writes these three and then stops: Zig provides no libc for
`wasm64-emscripten`. The two options modules record the exact feature and
target choices (kitty graphics, which Ghostty turns off for freestanding
targets, is on for this one).
`wuffs-c.zig` is translate-c's output for Wuffs' header in the same build
(Ghostty's `pkg/wuffs`), which kitty graphics take; translate-c is not built
inside Dolly.

The Unicode tables are not here: `ghostty-build` generates them as Ghostty's
build does, running uucode's generator on its UCD files and Ghostty's two over
its tables, each a program of the image's Zig (`Dollyfile-ghostty-build`).
