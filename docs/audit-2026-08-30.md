# Project audit — 2026-08-30

This is a point-in-time verification record. Findings are preserved as they
were measured; use [`roadmap.md`](roadmap.md) and
[`port-status.md`](port-status.md) for current priorities and implementation
status.

This document records a whole-project engineering audit of Dolly at its current
proof-of-concept stage. It is intentionally candid: a successful browser demo
is evidence for the thesis, but it does not by itself establish a stable ABI,
Node compatibility, reproducible builds, or production hardening.

## Scope and method

The final review covered all 132 project files outside `node_modules`, `build`,
`dist`, and downloaded caches: 258,703 lines. Of those,
233,478 lines are the generated Unicode table
`src/ghostty/generated/uucode-tables.zig`. All maintained source, scripts,
contracts, configuration, tests, and prose were reviewed directly. Large
machine-generated Ghostty tables were reviewed through their generator/source
manifest, pinned inputs, checksums, and compile-time/browser use rather than by
pretending that manual inspection of every numeric table entry is meaningful.

The reviewed surfaces were:

| Surface | Authoritative files |
| --- | --- |
| Project rules | `AGENTS.md` |
| Machine and device contracts | `abi/*.wat`, `include/dolly/*.h`, `config/browser-imports.json` |
| Runtime and loader | `src/dolly.c`, `src/compiler.cpp`, `src/system-snapshot.c` |
| Browser boundary | `src/runtime-worker.mjs`, `src/browser.mjs`, `src/http-policy.mjs`, `src/browser-broker.js` |
| Userspace | `src/slop.c`, the remaining non-inline `src/commands/*`, `Dollyfile*`, and `modules/*.dm` |
| Network compatibility | `src/libcurl-fetch.c`, `include/dolly/http.h`, `abi/dolly-http-0.wat` |
| Language/runtime adapters | QuickJS, Janis, native Zig, and Ghostty sources under `src/` |
| Build and provenance | `scripts/*`, `toolchain/CMakeLists.txt`, `config/source-pins.sh`, patches/manifests |
| Product surface | `index.html`, Pi packaging/extensions, all documentation |
| Verification | `test/dolly.test.mjs`, `scripts/browser-harness.mjs`, fixture routes |

Review techniques included contract/interface comparison, import-closure
inspection, source and generated-artifact provenance checks, error-path review,
shell and JavaScript syntax checks, native warning-clean compilation where
applicable, static contract tests, a dependency audit, and the real Chrome
acceptance proof.

## Architectural conclusion

The central design is coherent and worth continuing.

1. The security perimeter is the outer main-module import closure. Internal
   commands share memory and are not security principals.
2. `env.dolly_http_dispatch` is the only intentional agent-selected network
   edge. The framebuffer, input ring, startup assets, clocks, entropy, loader
   glue, and bootstrap text sink are separate device or initialization
   facilities, not general communication APIs.
3. WasmFS is genuinely in the WebAssembly machine. There is no host directory
   mount or Node filesystem provider.
4. Filesystem executables are real wasm64 dynamic modules with a typed entry
   point and shared memory/table, not command registrations or multicalls.
5. The source-build workflow is already a useful requirements-discovery tool:
   Make, Git, curl, QuickJS, Zig, Ghostty, and Pi have exposed much more of the
   real agent contract than toy programs alone would have.

The largest architectural debt is also clear: `dolly-0` is currently a broad,
Emscripten-libc-shaped dynamic-linking contract. It is a valuable probe, but it
should not be frozen as Dolly's long-term platform substrate.

## Corrections made during the audit

### Executable integrity and lifecycle

- Filesystem modules are now structurally validated and required to carry
  exactly one matching `dolly.abi` digest immediately before every `dlopen`.
  Previously, the in-Wasm compiler validated its own output, but a file written
  by another program could reach the runtime loader without that check.
- The display driver is subject to the same runtime validation.
- Compiler output is fully linked, validated, and stamped before publication.
  It uses atomic rename where WasmFS supports it and a synchronous bounded copy
  across preloaded backend boundaries; failed copies remove the target.
- `dolly_getrandom` now fills arbitrarily sized requests in legal 256-byte
  `getentropy` chunks rather than failing beyond the host API's per-call limit.
- `dolly_sleep` now performs a worker-local atomic wait instead of claiming to
  sleep while returning immediately.

These checks improve correctness and make the executable contract real at its
consumption point. They are not an internal security boundary: a fully
compromised Dolly userspace can still corrupt the shared runtime, which the
threat model already permits.

### Slop and command semantics

- Absolute one-component globs such as `/b*` now enumerate `/` instead of `.`.
- Invalid numeric arguments to `exit` now diagnose and terminate with status 2
  rather than silently becoming status 0.
- Interactive overlong lines are drained before the next prompt.
- `set -e` no longer exits on the non-final left side of `&&` or `||` lists.
- `touch` updates timestamps on existing files instead of merely opening them.
- `mkdir -p` rejects an existing non-directory.
- recursive `rm` uses `lstat`, does not traverse a symlink, and refuses root,
  `.` and `..` spellings.
- the curl command now distinguishes ordinary requests from explicit `-L` /
  `--location` redirect intent.
- command help includes Janis.

Slop remains intentionally finite. Command substitution failure handling,
expansion timing across a multi-command parsed script, redirection ordering,
field splitting, and concurrent pipelines are documented compatibility gaps,
not accidental claims of full POSIX conformance.

### JavaScript compatibility honesty

- Janis's placeholder digest routine was replaced with exact MD5, SHA-256, and
  HMAC implementations, covering the algorithms measured in upstream Pi.
- `timingSafeEqual` now examines the full equal-length input and follows Node's
  unequal-length error behavior.
- zlib methods no longer return their input while pretending it was compressed
  or decompressed; the absent binding fails explicitly.
- `child_process.exec` and `execFile` no longer execute a command twice while
  constructing their return object.
- relative `..` path normalization and root path formatting were corrected.

Janis is still a compatibility layer, not Node. Every remaining method needs to
be classified as exact, deliberately simplified, or unsupported; API presence
alone must never be treated as evidence of compatibility.

### Build, startup, and serving

- One True Awk now goes through the maintained Make target rather than a second
  duplicate startup recipe.
- Git is configured with `/bin/slop` as its shell path; the nonexistent
  `/bin/sh` is no longer embedded.
- Git's private helpers install into the existing `/usr/libexec/dolly`
  directory instead of requiring a hidden file solely to materialize another
  preloaded directory.
- an obsolete Pi runtime asset and an unused Emscripten runtime-method export
  were removed.
- both development and browser-test static servers now expose only the page,
  three browser modules, and `dist/`. They no longer turn every file in the
  host checkout into a same-origin HTTP-readable asset.
- snapshot documentation was updated to describe one packaged static build
  artifact rather than hostname- or profile-scoped browser persistence.

## Open findings and risk register

### P0 — preserve the containment claim

1. **Hardened HTTP policy must be mandatory outside development.** The default
   broker deliberately permits arbitrary HTTP(S) destinations. That is useful
   for a demo and unsafe for secrets. A deployment must install exact
   origin/path/method rules, permit only the sandbox credential-header names
   required by each matched destination, reject redirects, and bound bytes,
   time, and request count. Credential values remain inside Dolly; the broker
   does not own or inject them.
2. **Guard the browser import closure continuously.** Any new import can become
   a host capability. Import review must remain a release gate, not a static
   allowlist that grows whenever a port fails.
3. **Add whole-worker resource governance.** HTTP has finite quotas, but CPU
   loops, memory growth, terminal flooding, and compiler bombs currently rely
   mainly on terminating the worker. A trusted supervisor should have explicit
   time, memory, output, and restart policy without adding guest authority.

### P1 — make the userspace contract credible

1. **Define the platform substrate below libc.** Derive path/descriptor, clock,
   entropy, lifecycle, and network operations from observed ports; rebuild libc
   and multiple runtimes above that smaller versioned ABI.
2. **Finish command teardown.** A command's relocated static data is reset, but
   allocator state, leaked descriptors, `atexit`, TLS, and libc signal state can
   survive between invocations. Track resources by command epoch and reclaim or
   reset them at `wait`.
3. **Make snapshot construction declarative.** `system_files[]` is an explicit
   and safe allowlist, but it duplicates knowledge from the startup graph. A
   Dollyfile/manifest compiler should generate the build script, retained-file
   manifest, checks, and metadata from one reviewed recipe.
4. **Resolve redirect semantics.** `DOLLY_HTTP_FOLLOW_REDIRECTS` records caller
   intent, while the version-0 browser provider always rejects redirects. Keep
   the safe default, then either remove the promise or implement policy-checked
   manual redirects where every hop is separately authorized.
5. **Turn Janis into a measured contract.** Build a conformance inventory and
   test each API used by Pi/extensions against Node fixtures. Bind real zlib
   through Dolly's source-built archive when a workload requires it.

### P2 — complete the agent workflow

1. Run a pinned TypeScript compiler in Janis and build Pi from TypeScript source
   inside Dolly; retire the host-generated application bundle.
2. Complete Git's remote-helper protocol so normal `git clone`, `fetch`, and
   dependency-free extension installation work through the single HTTP edge.
3. Replace regex-heavy implementation tests with more black-box executable and
   browser behavior where practical, while keeping exact ABI/import inspection.
4. Add accessibility and incremental damage rendering only through narrowly
   reviewed display contracts. Preserve the implemented character selection
   and explicit-user-action clipboard bridge as part of that small contract.
5. Establish reproducibility evidence: two clean builds should produce the same
   ABI digest, source manifest, recipe result, and preferably byte-identical
   system capsule. Two consecutive audit builds produced the same system
   snapshot digest but different outer runtime build IDs, so nondeterminism in
   the main runtime/data packaging remains to be isolated.

### Deferred by design

- permissions, users, `chmod`, and execute bits;
- internal isolation between commands;
- native processes, worker threads, background jobs, or performance parity;
- raw TCP/UDP/DNS/TLS sockets;
- native Node addons and arbitrary npm lifecycle scripts;
- a full Ghostty desktop application inside Wasm;
- hiding sandbox memory from the trusted embedding page.

These are not free TODOs. Each needs a demonstrated agent workload and a design
that does not blur the browser capability perimeter.

## Supply chain and generated code

`config/source-pins.sh` is the canonical source manifest. The Emscripten image
is digest-pinned; release archives use SHA-256; Git sources use exact commits;
patches and generated-source manifests are checked into the project. Generated
Ghostty Unicode files carry local checksums. Host-generated Pi packaging is
version-asserted but remains an intentional transitional trust/build step.

`npm audit --omit=dev` reported zero known vulnerabilities on 2026-08-30 for
the installed graph. That is only a registry advisory check; it does not attest
to behavioral compatibility, source reproducibility, or the safety of bundled
JavaScript.

## Audit standard going forward

A new tool is not “supported” because it compiles once. Its acceptance record
should state:

1. exact pinned source and any patches;
2. target-side build command;
3. imports added or proven unnecessary;
4. filesystem/lifecycle/network behavior exercised;
5. unsupported paths and their explicit failure;
6. repeat invocation and clean snapshot boot evidence;
7. whether it changed the browser capability boundary.

That record turns each port into evidence about the minimal agent API rather
than allowing Dolly to drift into an undocumented Linux imitation.
