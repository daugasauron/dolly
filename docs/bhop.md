# Airtime agents

`Dollyfile-bhop` starts the original Foundry course with an agent overlay.
The course, physics, collisions and game rendering are unchanged. `bhop` still
runs the standalone game; `bhop-agent` runs it with the overlay.

Settings selects OpenRouter or Codex (local proxy), a vision/tool-capable model,
and reasoning effort. OpenRouter supports browser authorization or an API key.
For Codex, upload the configuration generated by `scripts/codex-relay.mjs`, as
described in [the ClassiCube setup](classicube.md). The relay uses your local
subscription; Pi and the game execute inside Dolly.

Backtick switches between you and the agent. Tab hides/shows the overlay; F11
toggles fullscreen. Enter opens a prompt and sends it. Escape interrupts the
agent; a new instruction can steer it or replace the task with Ctrl+Enter.
Settings and reasoning traces have separate panels. Cost remains visible and
there is no task duration or cost cap. Five seconds after finishing, the agent
receives an instruction to review its attempt and try again. Interrupting,
taking control, or opening Settings pauses continuation; provider failures
retain their explicit Retry action.

The only agent tools are `game_input` and `review_attempt`. Their inputs are
keyboard/mouse events and their observations are the unmodified 960×540 game
framebuffer, including its normal HUD. They expose no shell, map, coordinates,
velocity, collision queries or practice/checkpoint shortcuts.

`game_input` accepts up to 128 segments totaling at most 30 seconds. Each
segment has a duration in the game's existing 10 ms ticks, simultaneous held
keys, and optional total relative mouse deltas. Mouse deltas have 0.001 CSS
pixel precision and are spread across the segment with their exact sum
preserved. Positive x turns right and positive y looks down. One CSS pixel is
0.0011 radians. Keys persist across adjacent segments and release when the
batch ends or you interrupt. Space jumps on a new press; either wheel
direction also queues a jump. R uses the game's ordinary full-course restart.
The game keeps running while the model responds.

Agent control records a PNG every ten simulation ticks (100 ms), including
between tool calls. Taking control or pressing R starts a recording attempt.
The input tool returns sampled frames from its batch. `review_attempt` can
retrieve up to four exact archived frame indices to inspect a failed jump;
an empty input batch gets a fresh screenshot. The model receives image timing
and the inputs it requested, without hidden game state.

Review attempts pauses the agent and downloads a standalone HTML timeline with
an attempt selector, frame slider, playback and actual input events. Recordings
remain in `/workspace/bhop-runs/run-*/attempt-*`. PNGs and `frames.jsonl` contain
frame indices and timing; `inputs.jsonl` contains delivered keys, mouse deltas
and tick numbers. Recordings grow while the agent has control.
HTML exports use Dolly's existing 64 MiB download limit; longer recordings
remain available to the agent through frame review and as individual PNG files.

Settings, conversation, draft, usage and `idle-prompt.txt` live under
`/home/dolly/.config/bhop`. Dolly session saves retain these files and recorded
attempts. Restoring starts at the course's normal start in human control and
does not start inference automatically. The saved `recording-run.txt` keeps
previous attempts available for review; new attempts continue their numbering.

Build with `npm run image -- bhop`. The module compiles the input adapter and
shared SDL viewer inside Dolly. Its private filesystem input protocol is an
application protocol, with no new browser imports or network capabilities.
`node --test test/bhop*.test.mjs` checks course preservation and input encoding.
`DOLLY_IMAGE=bhop DOLLY_BROWSER_MODE=bhop-agent scripts/test-browser.sh` tests the
OpenRouter path with scripted inference and the real game. Use
`DOLLY_BROWSER_MODE=bhop-agent-live` and `DOLLY_BHOP_MODELS_FILE=/path/to/models.json`
for a live subscription attempt (with the same `DOLLY_IMAGE=bhop`).
