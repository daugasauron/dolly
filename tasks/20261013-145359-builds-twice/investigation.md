# Part B: what is compiled more than once

## Summary (findings, no advice)

1. Of the nine repeats, three are the same source at the same pin and were never compiled to the same bytes: sbase (`c546c3a5`, staged tar `c05c6463…`) in three recipes with the same flags for 44, 8 and 1 disjoint tools, where sbase's `Makefile:94, 234-238` links every tool against `libutf.a` and `libutil.a`, so those two archives are built three times; IJG libjpeg 9f (`04705c11…`) in `xonotic-build` as 46 units at `-O1` and in `wine-build` as 26 decoder units at `-O2 -fno-strict-aliasing -pthread -w`; Zstandard 1.5.7 (`eb33e51f…`) in `mojo-llvm` as three `lib/` directories at `cc -O2` with no defines and in the `zstd` package as those plus `dictBuilder` and three legacy decoders with upstream's `-DXXH_NAMESPACE=ZSTD_ -DZSTD_LEGACY_SUPPORT=5 …`.
2. Each second copy was made without a package to install: libjpeg's second (`3a50bdfc`, 2026-10-09, no body) came two days after the first (`bb95315c`: "libjpeg 9f is pinned and built in the image from its sources"); `mojo-llvm`'s Zstandard (`319c3a34`, 00:16 on 2026-10-13) came eight hours before the `zstd` package (`40944e63`, 08:58), whose pin comment says "Zstandard's is the one pinned for Mojo above" (`source-pins.sh:325`); the `sbase` and `tar` packages (`2d1ad59b`, 09:06 the same day) were made "from the archive system-tools already stages" and sit on `tools-build` for their pages.
3. The "different on purpose" readings hold on the record: Neovim's Lua 5.1 is upstream's requirement (`CMakeLists.txt:193`); Slopyard's 5.5.1 arrived on 2026-09-27 (`018c5f27`, "controllers now use in-sandbox-built Lua 5.5.1", a Codex task's progress note) with no reason recorded for the version; premake's bundled Lua is 5.3 (`contrib/lua/src/lua.h:19-20`), upstream's choice.
4. Box3D: `gamedev-sdk` compiles it with `-DBOX3D_DISABLE_SIMD` and replaces `timer.c` by `box3d-platform.c`, whose comment says "Dolly deliberately executes tasks serially inside one Wasm userspace, so synchronization objects carry no host capability and worker handles are inert" (2026-09-03 and before, `07a3cf1e`); Slopyard's second build (`53560d3f`, 2026-09-25) exists because "The pinned Box3D already has an SSE2 path for WebAssembly … A source-only wrapper applies Clang's `target("simd128")` attribute" and measured "about 6.8% less simulation time", and since `463ee297` (2026-10-06) defines `__EMSCRIPTEN__` so Box3D takes its thread path, because without it "b3CreateThread runs the worker loop inline and never returns: … slopyard --check span at full CPU for 71 minutes".
5. fmt: 7.1.3 was Dolly's own pick for 0 A.D. (zero-ad-deps investigation §1.3, 0 A.D.'s floor is 5.3.0); 11.1.1 is bundled inside OpenAL Soft 1.24.3's tree; 11.2.0 is Mojo's pin (`bazel/common.MODULE.bazel:10`), compiled as one unit (`format.cc`) into a `third-party` archive with xxHash (`bazel-to-cmake.py:40`). Three upstreams' choices, one of them Dolly's.
6. termcap: `less` links GNU termcap 1.3.1 built inside its recipe and does not export it ("it is not exported, since nothing else asks for it", less task `:129`; it came 2026-10-08); Emacs builds its own `termcap.o tparam.o` (`emacs-dolly.patch:19-20, 28-29`: "Dolly has no terminfo library; use Emacs's termcap, as MS-DOS does"); `libterminfo` (2026-10-13) exists because tmux needs `setupterm`, which "GNU termcap, which `less` uses, has no" (tmux task `:49`). NetBSD's `termcap.c` defines `tgetent`, `tgetflag`, `tgetnum`, `tgetstr`, `tgoto` (`:52-180`), the five of less's six; `tputs` is in its `tputs.c`. Whether less links and runs on it is not tried.
7. LLVM three times is three revisions (Part A §A2.3), two of them "24.0.0git"; inside the `llvm` demo one archive is extracted three times and TableGen run twice, which the task explains by snapshots keeping no mtimes.
8. ggml twice is two revisions vendored by two engines at two flag sets (Part A §A2.2).
9. The repeated `SOURCE` rows are as counted: `stb_truetype.h` in `ghostty-build`, `bhop`, `classicube`, `rts-arena`; `sbase.tar` in `system-tools`, `sbase`, `tar`; `llvm-project.tar.gz` in the three `llvm` recipes; `llvm-host-triple.patch` in `llvm-tablegen`, `llvm-build`, `rust-llvm`, `mojo-llvm`, served at three site paths with one digest.
10. Not findable without building: whether NetSurf's JPEG decoding is the same with the 46-unit library at `-O1`; whether LLVM's zstd use links against the package's namespaced `libzstd.a` beside Mojo's own xxHash (`XXH_*` symbol names differ between the two builds); whether `less` works on `libterminfo` with Dolly's `TERM=xterm-256color`; the size of `libjpeg.a`; the memory of `tools-build` for eight sbase tools.

## B4. A shared package on real cases

### (d) IJG libjpeg as a package `xonotic-build` and `wine-build` install

```text
DOLLY 7
PACKAGE libjpeg
REQUIRES HOST runtime@0
FROM    /vX/Dollyfile-system-tools <sha>              # cc, ar, make; nothing else
REQUIRES HEADER libc
REQUIRES TOOL   ar cc cp make
SOURCE  /vX/dist/static/libjpeg/jpegsrc.v9f.tar.gz <sha> /tmp/jpeg.tar.gz   # the row at source-pins.sh:204-207, staged as its own file
SLOP gzip -dc /tmp/jpeg.tar.gz | tar -xf - -C /tmp
SLOP cp /tmp/jpeg-9f/jconfig.txt /tmp/jpeg-9f/jconfig.h                     # the generic configuration (makefile.ansi), as both demos do
FILE /tmp/jpeg.mk
    .RECIPEPREFIX := >
    S := /tmp/jpeg-9f
```

### (f) sbase's three recipes from one archive
