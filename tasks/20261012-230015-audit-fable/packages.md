## Findings, ranked by value for effort

**1. `audio-sdk` and `gpu-sdk` are empty images; nena makes their one purpose a command.** Evidence: byte comparison of `work/rust/dist/dolly-gpu-sdk-system.snapshot` against `system`: 0 files added; `audio-sdk` has the same 15-line shape (`Dollyfile-audio-sdk`) and zero `FROM` descendants; `gpu-sdk` has three (`gpu-fluid`, `mojo-gpu`, `mojo-runtime`), all of which already declare `gpu@0` themselves (hosts are never inherited, `docs/dollyfile.md:202`). Users: `config/domain-pages-images.txt`, `config/github-pages-images.txt`, seven tests (`test/audio-browser.mjs`, `microphone-browser.mjs`, `gpu-indicator-browser.mjs`, `gpu-render-browser.mjs`, three `.test.mjs`). Why: two of 54 opened images exist to pin one `REQUIRES HOST` line; with nena, "a shell with a GPU" is `default` plus `nena enable gpu`. Do: delete `audio-sdk` now (config lists, tests open `system` with the module added as `displayProbe` does); repoint the three `FROM gpu-sdk` to `system`, delete `gpu-sdk`. Cost: cheap edits; the repoint rebuilds `gpu-fluid` and `mojo-runtime` to `mojo` to `mojo-gpu`, no seed change. Confidence: high.

**2. What nena makes unnecessary, beyond the two SDKs.** `Dollyfile:16-17` declares `dso`, `sockets`, `threads` "since an image's list is fixed"; with `bridges@0` the list is not fixed and `default` declares only what its own programs use. Held item 6 of the packages task (`transcribe`, `voice`, an `openal` or `llama` package refused by `default`) dissolves, as does the rule "a host-module set without files is not a package" (`tasks/20261012-130814-packages/TASK.md:40-42`). Images that are only base + package + module + entry: `rust-tools` (18 lines, no start script: delete, it is `amy install cargo`), `mojo-gpu` (38 lines: three example `.mojo` files and a build check; move the examples into the `mojo` package under `/usr/share/doc/mojo` and delete the image, or keep it as the demo's route), `speech-to-text` (21 lines) and `pi-phone` (34) keep their routes because a visitor needs the start script. What stays: `REQUIRES HOST` in packages is nena's input; the recipe-time `INSTALL` check; every toolchain. Cost: cheap edits after nena lands. Confidence: high.

**3. `default` cannot diff, patch, unpack a `.tar.gz`, or create an archive.** Evidence: `diff` and `patch` are in the `git` package (`Dollyfile-git:7-9`) because they run `git diff --no-index` (`src/commands/diff.c:7`); Dolly's `tar` says "This tar extracts only; git archive creates archives" (`Dollyfile-system-build:2012`); `default` installs `core posix display curl amy` only (`Dollyfile:18-22`), no `gzip`, no `less`. Why: an agent's first moves are `diff`, `tar czf`, `curl | tar xz`; "Agents are effective through shells and conventional command-line tools" (AGENTS.md). Do: `default` installs `git` (10,262,566 bytes), `gzip` (508,918), `less` (776,709): 14.4 MB becomes about 26 MB; the `.dollyrc` already recommends `amy install git`. Cost: a repin of `default`, blocked by finding 4. Confidence: high.

**4. `zero-ad` is `FROM default`: the heaviest image pins the lightest.** Evidence: `demos/zero-ad/Dollyfile-zero-ad` `FROM /v0.1.2/Dollyfile` (1,930,629,960-byte snapshot); the packages task records that touching `default` means "one more rebuild, of an image this tree cannot make" (line 214). Why: every improvement to the image people open costs a 0 A.D. build. Do: make `zero-ad` a root composition (`INSTALL core posix display …` plus its 13 `COPY` rows and one `SLOP`), or `FROM system`. Cost: one `zero-ad` rebuild, then `default` is free. Confidence: high.

**8. `amy` gaps, and what not to add.** (a) `amy files NAME` for an uninstalled package fetches the whole snapshot to print a list (`amy.c:264-276`): `amy files rust` is a 463 MB download. Publish the list beside the index or in the receipt. (b) No `remove`, although `/etc/dolly/files/NAME` already holds the exact file list (`amy.c:207-216`): remove is unlink plus dropping the row, refusing paths another installed package lists. (c) A session saved on release N and opened on N+1 shows its packages as "-" (`find_row` matches the exact pin, `amy.c:129-135`) and `amy install` lays new files over the old: without remove, upgrade is accumulation. (d) `amy info` should print the `INSTALL` rows once dependencies are by reference. Do not add: search (`amy list | grep`), versions, a solver or lock file, a local cache, a second registry, signatures beyond pins. The index (name to pin and prose) and the catalog (`dist/dolly-images.mjs`, pin to snapshot) are one generator's two projections (`scripts/generate-routes.mjs:62-68`, `host/packages/service.mjs:30`); the only unpinned step is the name lookup, which is the point. Confidence: high.

## What is right and should stay

- Pins that cascade, so every image is replicable from its recipe chain, and the index as a plain text file with pin-only service lookups (`host/packages/service.mjs`): the only unpinned step is a name.
- The package rule (program, library with a port, data set) and "a library installs no compiler": it decided 49 rows consistently.
- Thin view packages over the builders: zero rebuild cost per new package was what let fifteen land in one night.
- Descriptions outside the pin, and the test that fails by name for a package nobody installs and uses.
